# Relay

Relay - проект на Unreal Engine 5.8 и C++, который я делаю в три части. Первая часть - UI-фреймворк на CommonUI: роутер экранов со слоями, асинхронная загрузка экранов с отменой, навигация через данные и фокус, который работает с геймпадом, клавиатурой и мышью. На нём сделаны магазин, диалог подтверждения, тосты и настройки. Дальше будут сетевой геймплей на GAS и сборка под Android с бюджетами памяти.

## Что уже работает

- Экраны открываются и заменяются по gameplay-тегу и закрываются через один роутер на локального игрока. Слоёв три: HUD, Menu и Modal.
- Классы экранов грузятся асинхронно. Новый запрос на слой отменяет старый, а закрытие экрана отменяет загрузки, которые уже не нужны.
- Back, горячие клавиши меню и кнопки навигации - это данные в WBP, без логики в Blueprint.
- Меню, магазин, диалог и настройки управляются геймпадом, клавиатурой и мышью. При смене устройства фокус остаётся там, где его оставил игрок, и не уходит с экрана, который принимает ввод.
- Пока открыто меню, игровой ввод выключен. Когда закрывается последнее меню, управление возвращается игре через режим Game у HUD.
- Магазин: вкладки категорий, виртуальный список с переиспользованием строк, панель деталей, иконки грузятся асинхронно с отменой. Покупка идёт через диалог подтверждения, цену и баланс проверяет кошелёк. Новый товар или категория - правка одного DataAsset, без кода.
- Тосты: на экране не больше трёх, остальные ждут в ограниченной очереди. Видны поверх любого экрана и не забирают ввод.
- Настройки: качество, масштаб разрешения, VSync и громкость. Применяются и сохраняются по Apply, а при выходе с несохранёнными правками экран спрашивает, уходить ли.
- Отладочный оверлей (`Relay.UI.ShowStats 1`): живые виджеты, созданные и переиспользованные строки списка, загрузки иконок, время открытия экрана.
- Правила для виджетов (без Tick и без property binding) проверяет компилятор виджетов, а реестр экранов проверяется при сохранении.

## Сборка и запуск

Что нужно:
- Unreal Engine 5.8.
- Visual Studio 2022 17.14 (MSVC 14.44.35211 и новее) или Visual Studio 2026 (MSVC 14.50.35723 и новее) с нагрузкой «Game development with C++». UE 5.8 работает с этими версиями, а несколько более старых отклоняет.
- Git LFS. Перед `git clone` выполнить `git lfs install`. Клон скачивает около 130 МБ ассетов, в основном манекен из шаблона. В архиве «Download ZIP» вместо ассетов могут оказаться только указатели LFS, и тогда проект не откроется.

```
"<UE_5.8 root>\Engine\Build\BatchFiles\Build.bat" RelayEditor Win64 Development -Project="<repo>\Relay.uproject" -WaitMutex
```

Потом открыть `Relay.uproject` и нажать Play. Поверх уровня шаблона открывается главное меню с кнопками Play, Shop и Settings. Play закрывает меню и отдаёт управление персонажу, а клавиша меню открывает его снова.

| Действие | Мышь и клавиатура | Геймпад |
|---|---|---|
| Переместить фокус | стрелки или мышь над кнопкой | крестовина или левый стик |
| Нажать кнопку в фокусе | клик, Enter или пробел | A |
| Назад (закрыть верхний экран) | Escape | B или Start |
| Следующая и предыдущая вкладка магазина | E и Q | RB и LB |
| Открыть меню во время игры | Escape | Start |

Кнопки геймпада названы по Xbox. На DualShock: A - крест, B - круг, Start - Options.

Отладочные консольные команды (нет в Shipping):
- роутер: `Relay.UI.Push <тег UI.Screen>`, `Relay.UI.Replace <тег UI.Screen>`, `Relay.UI.Close <тег UI.Layer>`;
- оверлей и замеры: `Relay.UI.ShowStats 1`, `Relay.UI.ResetStats`, `Relay.UI.ListInvalidation 0|1`, `Relay.UI.IconLoadDelay <секунды>`;
- тосты: `Relay.UI.Toast [текст]`, `Relay.UI.ToastBurst [число]`;
- кошелёк: `Relay.Shop.Give <монеты>`, `Relay.Shop.Buy <Id товара>`, `Relay.Shop.Reset`, `Relay.Shop.Dump`.

## Архитектура

- **Relay** - игровой модуль: классы шаблона Third Person, кошелёк и каталог магазина, настройки игры. Про UI он ничего не знает и от UMG не зависит.
- **RelayUI** - весь UI. Модуль `ClientOnly`: выделенный сервер его не собирает и не грузит. От игрового модуля он зависит только в одну сторону: RelayUI -> Relay.
- В папках `Public` только то, что можно подключать из других модулей. Категории логов и настройки UI лежат в `Private`.

```
URelayUIRouterSubsystem (один на локального игрока)
  -> WBP_RootLayout (URelayRootLayout)
       HUDStack    UI.Layer.HUD     нижний
       MenuStack   UI.Layer.Menu    над HUD
       ModalStack  UI.Layer.Modal   над меню
  -> DA_ScreenRegistry: тег UI.Screen.* -> класс виджета + слой
  -> IMC_UI: Back, OpenMenu (включён всегда)
URelayFocusSubsystem (один на локального игрока): фокус при смене устройства
URelayToastSubsystem (один на локального игрока): очередь тостов -> ToastLayer над ModalStack

ARelayPlayerState -> URelayWalletComponent (Relay): баланс, купленное, покупка по Id
  -> DA_ShopCatalog: категории и товары, иконки по soft-ссылкам
URelayShopViewModel (RelayUI) читает кошелёк и каталог, виджеты читают только viewmodel
```

API роутера:
- `PushScreen(Tag)` открывает экран поверх его слоя.
- `ReplaceScreen(Tag)` открывает экран вместо верхнего экрана слоя.
- `RequestCloseScreen(Screen)` закрывает экран, если он согласен. Через него идут Back и кнопки закрытия.
- `RequestCloseTopScreen(LayerTag)` - для отладки и инструментов.

На старте роутер открывает HUD и поверх него главное меню. Когда слой меню пустеет, верхним снова становится HUD, и включается его режим Game.


## Решения

По каждому решению: что я отверг и чем за него плачу.

**Стеки CommonUI и свой тонкий роутер поверх.**
- Отверг: свой стек экранов на чистом UMG.
- Почему: CommonUI уже умеет фокус, Back с геймпада, блокировку игрового ввода под меню и смену устройств ввода. Писать это руками - значит писать UI-фреймворк с нуля.
- Цена: стек CommonUI переиспользует объект закрытого экрана, не умеет replace и анимирует каждое изменение. Корневой лейаут выключает переходы на всех слоях: во время перехода стек считает активным уходящий экран. Replace роутер делает как «добавить, потом убрать». Маршрутизацию ввода в CommonUI трудно отлаживать, а некоторые ошибки в настройках ломают её без единой ошибки в логе.

**Один роутер на локального игрока, подсистема LocalPlayer.**
- Отверг: подсистему GameInstance, как в Lyra (там нужен ещё отдельный объект на игрока), или виджет, которым владеет HUD или PlayerController (он умирает вместе с контроллером).
- Почему: один роутер на игрока, без лишних менеджеров. Он живёт дольше любого контроллера и строит UI заново для каждого нового. Отладочную камеру роутер пропускает, поэтому её включение UI не сбрасывает.
- Цена: когда подсистема создаётся, контроллера и места во вьюпорте ещё нет, поэтому UI строится в `PlayerControllerChanged`. Стек экранов при смене карты не сохраняется.

**Экраны по тегу из одного реестра.**
- Отверг: экраны, которые держат ссылки на классы экранов, которые они открывают.
- Почему: в одном месте тег `UI.Screen.*` связан с классом виджета и слоем, и экраны друг о друге не знают. До стеков может добраться только роутер: `URelayRootLayout::FindLayer` приватный, а роутер - его friend. При сохранении реестр сообщает о пустых тегах, отсутствующих или удалённых виджетах и неизвестных слоях.
- Цена: один ассет и один список тегов на все экраны. Blueprint лейаута всё ещё может вызвать Push Widget у своих стеков в обход роутера - это правило команды, а не компилятора.

**Асинхронная загрузка экранов, не больше одного ожидающего запроса на слой.**
- Отверг: синхронную загрузку или очередь из всех запросов.
- Как: класс экрана грузится по soft-ссылке, а если уже в памяти, экран открывается в том же кадре. Новый запрос на тот же слой отменяет ожидающий. Закрытие экрана отменяет ожидающие запросы на его слое и на всех слоях выше: модалка, которую запросило закрытое меню, уже не нужна. Новый контроллер отменяет всё.
- Гонка: колбэк, который уже стоит в очереди, гасит только `FStreamableHandle::CancelHandle`, а если просто отпустить handle, колбэк всё равно придёт. Ещё у каждого запроса есть номер, и устаревший колбэк сразу выходит. Запись об ожидании создаётся до `RequestAsyncLoad`: при `s.StreamableDelegateDelayFrames=0` колбэк может прийти прямо внутри вызова.
- Цена: если нажать Shop, а потом Settings до того, как Shop загрузился, откроются только Settings. Индикатора загрузки пока нет.

**Экран закрывается через роутер и может отказаться.**
- Отверг: поведение CommonUI по умолчанию, где Back сразу деактивирует экран.
- Почему: Back, кнопки закрытия и Replace один раз вызывают `URelayScreen::HandleCloseRequest()`. Настройки с несохранёнными изменениями возвращают false и спрашивают, уходить ли.
- Цена: экраны знают роутер, хотя друг друга по-прежнему не знают. Blueprint может вызвать Deactivate Widget и обойти вопрос.

**Режим ввода принадлежит экрану, а контексты ввода переключает CommonUI.**
- Отверг: режим ввода в реестре, переопределение input config в Blueprint или роутер, который сам добавляет и убирает игровые контексты.
- Почему: магазин - это меню, откуда бы его ни открыли. `URelayScreen` читает перечисление (Menu или Game). CommonUI кладёт в Enhanced Input тег `InputMode.Menu` или `InputMode.Game`, а у игровых контекстов шаблона стоит фильтр по `InputMode.Game`, поэтому под любым меню они выключаются. `IMC_UI` не фильтруется никогда: клавиши Back CommonUI ищет только в применённых контекстах.
- Цена: переключение живёт в настройках ассетов mapping context, а не в коде (см. «Настройки, которые ломаются молча»). Каждый HUD-экран должен выставить Game.

**Теги UI в конфиге, а не нативные.**
- Отверг: `UE_DEFINE_GAMEPLAY_TAG` в RelayUI.
- Почему: UE 5.8 срабатывает ensure на нативных тегах в модуле, который грузится не на всех таргетах: дерево тегов у клиента и выделенного сервера должно совпадать. С включённой быстрой репликацией, как обычно с GAS, реплицируемые теги передаются индексами в этом дереве. Теги лежат в `Config/DefaultGameplayTags.ini`, код находит их по имени.
- Цена: опечатка в имени тега компилируется и падает ensure при первом обращении.

**Правила, которые проверяет компилятор, а не ревьюер.**
- Слои привязаны через `BindWidget`, поэтому лейаут без `HUDStack`, `MenuStack` или `ModalStack` не скомпилируется.
- Виджеты в `/Game/Relay/UI/` не компилируются с Tick в Blueprint, переопределённым OnPaint или property binding (`DefaultEditor.ini`). Привязки MVVM не могут работать в режиме Tick.
- `URelayViewModelBase` разрешает только способы Manual и Resolver: виджет не может создать viewmodel сам, он получает его готовым или через resolver. Так получают viewmodel магазин, строки списка, панель деталей, диалог и настройки.
- У каждой C++-базы виджета стоит `meta=(DisableNativeTick)`, потому что эта meta не наследуется.
- Цена: правила про Tick, OnPaint и property binding действуют только в `/Game/Relay/UI/`, контент шаблона они не проверяют. Ограничения MVVM действуют на весь проект.

**Навигация - это данные.**
- У `URelayNavButton` есть действие (открыть, заменить, закрыть свой экран) и тег экрана, а у экранов - список горячих клавиш (действие ввода -> тег экрана). Так HUD открывает меню.
- Цена: переход с условием потребует кода.

**Фокус.**
- При открытии экран ставит фокус на свой Desired Focus Widget, а `bAutoRestoreFocus` возвращает фокус на прежнее место, когда игрок возвращается на экран.
- Стиль Hovered CommonUI показывает только под курсором, а курсор на виджет в фокусе он водит только для геймпада. Фокус с клавиатуры показывает рамка `FocusFrame` в кнопке. Наведение мыши переносит фокус на кнопку, поэтому подсвеченная кнопка - та же, что нажмётся по Enter.
- `URelayFocusSubsystem` держит фокус на месте при смене устройства (см. «Грабли CommonUI» ниже).
- Цена: пока у кнопки фокус, Enter и пробел уходят ей, а не действиям ввода на этих клавишах. Исправление для смены устройства зависит от того, когда CommonUI запоминает цель фокуса, и после обновления движка его может понадобиться проверить.

**Деньги живут в игровом модуле, на PlayerState.**
- Отверг: подсистему LocalPlayer (живёт только на клиенте, в сетевой части её пришлось бы выбросить), подсистему GameInstance (один кошелёк на всех игроков) и баланс во viewmodel (модель оказалась бы в UI).
- Почему: деньги принадлежат игроку, а не пешке и не контроллеру. Кошелёк сам берёт цену из каталога, UI передаёт только Id товара. Проверка в UI - подсказка, решает модель: пока открыт диалог, баланс мог измениться. С сетью покупка станет серверным RPC, а UI останется тем же.
- Цена: свой PlayerState, и на сетевом клиенте он приходит позже UI. Покупка синхронная, с бэкендом она станет асинхронной. Покупки не сохраняются между запусками.

**Каталог - один DataAsset с проверкой при сохранении.**
- Отверг: DataTable (удобнее, когда товары ведут в таблице сотнями) и отдельный ассет на товар (нет конфликтов слияния, но нужен Asset Manager).
- Почему: новый товар или категория - это правка одного ассета. Категорию товара выбирают из выпадающего списка категорий этого же ассета. При сохранении ассет сообщает о пустых и повторяющихся Id, неизвестной категории, отрицательной цене и отсутствующей иконке.
- Цена: один ассет на всех дизайнеров и линейный поиск по Id.

**MVVM для значений, C++ для структуры.**
- Viewmodel у магазина и у каждого товара. Тексты, цены и флаги приходят в виджеты привязками MVVM. Элементы списка, выбор и вкладки подключает C++ экрана: привязка не передаст списку новые элементы и не вернёт выбор во viewmodel.
- Строка списка получает viewmodel в `NativeOnListItemObjectSet`, а не через расширение MVVM для списков: оно назначает viewmodel на кадр позже, и строка на кадр показала бы прошлый товар.
- Отверг: строки, которые сами читают каталог и кошелёк. Каждая строка подписывалась бы на кошелёк, а виджет знал бы про геймплей.
- Цена: 60 мелких объектов на всю сессию. Для десятков тысяч товаров viewmodel создавались бы только для видимых строк. MVVM в UE 5.8 - Beta.

**Список - `UCommonListView`, строка - кнопка CommonUI.**
- Отверг: ScrollBox с виджетом на каждый товар.
- Почему: список виртуальный, виджетов строк столько, сколько видно, и они переиспользуются. `UCommonListView` понимает строки-кнопки: Enter, A и клик доходят до `OnItemClicked`, а когда фокус приходит на список, он сам ставит его на выбранную строку. Выбор следует за фокусом, поэтому панель деталей одинаково работает с геймпадом, клавиатурой и мышью.
- Цена: строка обязана полностью сбрасываться при смене товара, иначе покажет чужие данные. Отсюда гонки с иконками.

**Иконки - свой `URelayAsyncImage`.**
- Отверг: `UCommonLazyImage` и `SetBrushFromSoftTexture`. У них защита только по пути к текстуре, а `SetBrush` не отменяет загрузку, которая уже идёт.
- Как: плейсхолдер, номер запроса и `CancelHandle`. Закрыты четыре гонки: строку переиспользовали до конца загрузки; экран закрыли; текстура уже в памяти (показываем сразу, без мигания плейсхолдера); пустая ссылка (колбэка не будет никогда). `Relay.UI.IconLoadDelay` задерживает показ, чтобы гонки было видно глазами.
- Цена: свой виджет. Отмена гасит колбэк, но чтение с диска не останавливает.

**Диалог подтверждения не знает, кто его открыл.**
- Роутер открывает его по тегу `UI.Screen.Confirm` и передаёт контекст: viewmodel с текстами и делегатом ответа. Ответ уходит ровно один раз при любом способе закрытия: Confirm, Cancel, Back, закрытие роутером. Фокус при открытии на Cancel, чтобы случайное двойное нажатие не тратило деньги. Тот же диалог спрашивает «уйти без сохранения?» в настройках.
- Отверг: диалог магазина, который знает про магазин, и шину сообщений (в движке её нет, Lyra подключает её своим плагином).
- Цена: роутер держит контекст живым, пока грузится класс диалога. Если эту загрузку отменили, ответа не будет, поэтому запросивший не должен ждать ответа, чтобы разблокировать себя.

**Тосты - не экраны.**
- Отверг: тост как активируемый виджет на стеке. Стек показывает один виджет, а активируемый тост забрал бы ввод у меню.
- Как: очередь в подсистеме игрока и отдельный слой над модалкой, который не принимает ввод. На экране не больше трёх тостов, очередь тоже ограничена, виджеты тостов берутся из пула. Очередь переживает пересборку UI.
- Цена: свой таймер на тикере ядра (реальное время, работает и на паузе). Анимаций пока нет.

**Настройки: правки отдельно от сохранённого.**
- Viewmodel держит отредактированные значения рядом с сохранёнными, игра меняется только по Apply. Back с правками экран не закрывает: `HandleCloseRequest` возвращает false и открывает диалог.
- Хранение: `UGameUserSettings` (свой класс добавляет громкость) и культура движка в `GameUserSettings.ini`. Своего файла сохранений нет.
- Отверг: применять каждое изменение сразу. Тогда «уйти без сохранения» пришлось бы откатывать в игре.
- Цена: в Play In Editor смена языка включает только предпросмотр языка игры, потому что смена культуры процесса переключила бы язык редактора. Разрешение окна экран не меняет.

**Отладочный оверлей на чистом Slate.**
- `SCompoundWidget` в обёртке `UWidget`, обновляется таймером Slate четыре раза в секунду. Показывает живые виджеты, созданные и переиспользованные строки списка, загрузки иконок и время открытия последнего экрана. `Relay.UI.ListInvalidation` выключает кэширование списка, чтобы сравнить.
- Цена: счётчики общие на процесс. Перебор всех `UUserWidget` дорогой, но только в отладке.

## Грабли CommonUI, на которые я наступил

- **A не прыгала.** HUD объявлял режим захвата мыши `CapturePermanently_IncludingInitialMouseDown`. В этом режиме аналоговый курсор CommonUI считает, что может отпустить мышь, и в игре превращал A в клик мышью, который съедался. Игровые экраны используют `CapturePermanently`, как в Lyra.
- **Крестовиной на Shop, потом Enter на клавиатуре - и нажимался Play.** При каждой смене устройства CommonUI ставит фокус на запомненный виджет экрана. Запоминает он его в событии Slate, которое приходит до смены фокуса, то есть запоминает виджет, с которого фокус ушёл. `URelayFocusSubsystem` просит его запомнить заново после каждой смены фокуса.
- **Неподвижная мышь забирала фокус.** Slate шлёт наведение виджету под курсором, даже если курсор не двигался, например когда под ним открылся новый экран. Наведение переносит фокус только после настоящего движения мыши, его записывает предпроцессор ввода (`FRelayPointerMotionTracker`).
- **Enter и пробел ничего не делали.** С UE 5.6 генератор проектов ставит `CommonButtonAcceptKeyHandling=TriggerClick` только для шаблона Blank, а проект из Third Person получает `Ignore`. Настройка прописана в `DefaultGame.ini`.
- **Консольные переменные CommonUI не применялись.** Генератор 5.8 пишет их в `DefaultGame.ini`, а `[ConsoleVariables]` движок читает только из Engine и Editor ini. Они лежат в `DefaultEngine.ini`.
- **Персонаж двигался под меню.** Для нового контроллера роутер копирует теги режима ввода CommonUI в Enhanced Input. Пока CommonUI не применил ни одного режима, он отвечает All, и два тега сразу оставляли игровые контексты включёнными. Теперь роутер ничего не пишет, пока режим не выбран.
- **Список держал фокус на себе, а не на строке.** Получив фокус, `UCommonListView` переводит его на выбранную строку, только если включён `bReturnFocusToSelection`. Магазин всегда выбирает товар заранее, и без флага Enter и A после открытия и после смены вкладки ничего не нажимали. Сеттер флага не экспортирован из UMG (`UListView` объявлен как MinimalAPI), поэтому экран ставит свойство через рефлексию до постройки Slate.
- **Смена устройства переводила фокус на кнопку по умолчанию.** Шаблон 5.8 включает `CommonUI.FallbackToDesiredOnAutoRestoreFailure`. При смене устройства CommonUI возвращает фокус на запомненный виджет, а если тот уже в фокусе, `SetUserFocus` возвращает false, и это считается неудачей: фокус уходил на Play. Переменная выключена в `DefaultEngine.ini`.
- **A на геймпаде нажимала то, что под скрытым курсором.** По умолчанию CommonUI превращает A в клик мышью в точке курсора, который водит за фокусом. При прокрутке списка курсор успевал оказаться над кнопкой Back. `CommonUI.ShouldVirtualAcceptSimulateMouseButton=0`: A нажимает виджет в фокусе.
- **После прокрутки фокус оставался на чужой строке.** SListView не всегда переводит фокус на строку выбранного товара, и фокус оставался на строке, которую список уже отдал другому товару. Строка выбранного товара забирает фокус сама, если фокус в списке.
- **При прокрутке стиком на миг подсвечивалась кнопка под списком.** Это был не фокус (видно по `SlateDebugger.Event.Start`), а hover от скрытого курсора геймпада. CommonUI ставит курсор в центр строки с фокусом (Link Cursor To Gamepad Focus), а SListView фокусирует частично видимую строку раньше, чем докручивает её, и её центр ещё под списком. Отключать привязку курсора хуже: hover остался бы на кнопке, где курсор встал. Между списком и соседними кнопками оставлен отступ не меньше половины строки.
- **Диалог открывался, а фокус оставался в магазине.** Строка, получившая выбранный товар при прокрутке, забирает фокус на следующем кадре (см. «После прокрутки фокус оставался на чужой строке»). Если A нажать, пока стик зажат, за этот кадр над магазином успевает открыться диалог, и строка уводила фокус из него. Теперь строка забирает фокус, только если её экран принимает ввод. Подстраховка от других таких гонок: `URelayFocusSubsystem` после каждой смены фокуса проверяет, что фокус на активном экране, и иначе просит CommonUI вернуть его туда.
- **Из диалога фокус уходил на экран под ним.** Навигация Slate геометрическая и не знает про экраны CommonUI. Экран отвечает на навигацию за свои границы `Stop`, и Slate ищет цель только среди его потомков. А закрытие экрана закрывает и экраны слоёв выше.
- **Громкость в Play In Editor не менялась.** У каждого запуска PIE своё аудиоустройство, а не основное устройство редактора. Настройки ставят громкость всем устройствам и каждому новому (`FAudioDeviceManagerDelegates::OnAudioDeviceCreated`).
- **В IMC_UI нет действия Confirm.** Этот контекст включён всегда и стоит выше по приоритету, поэтому действие на A или пробеле отняло бы эти клавиши у прыжка. Кнопки нажимаются через Slate и CommonUI.

## Где сломается

- **Глубокие стеки.** Экраны под верхним остаются живыми. Сто экранов в стеке - сто живых деревьев виджетов.
- **Переиспользованные экраны.** При повторном открытии стек возвращает тот же объект виджета. Экран, который не сбрасывает состояние в `NativeOnActivated`, покажет старые данные.
- **Первое открытие.** Экран появляется, когда загрузился его класс, и индикатора нет. Тяжёлый экран на слабом устройстве откроется с заметной задержкой.
- **Смена карты.** Каждый новый контроллер получает новый UI со стартовыми экранами, стек не восстанавливается.
- **HUD - это пол.** Управление возвращается игре только потому, что под меню лежит HUD в режиме Game. Если HUD не открылся, после закрытия последнего меню игра останется в режиме Menu без выхода. Роутер пишет об этом предупреждение.
- **Один корень ввода.** CommonUI отдаёт ввод одному активируемому корню, верхнему по отрисовке. Поэтому тосты не будут активируемыми.
- **Много экранов.** Один реестр и один список тегов в команде превратятся в конфликты слияния. Следующий шаг - реестр на фичу.
- **Нет паузы.** Пока открыто меню, мир продолжает работать.
- **Split-screen** не проверялся, хотя роутер сделан на игрока.
- **Сетевой клиент.** Кошелёк живёт на PlayerState, который приходит репликацией позже UI. Магазин, открытый до этого, будет пустым. Пока проект работает только без сети.
- **Повторное открытие экрана.** Закрытый экран стек отдаёт в пул без Slate, и строки списка уходят вместе с ним. При следующем открытии магазин создаёт строки заново: переиспользование работает в пределах одного показа.
- **Тысячи товаров.** Линейный поиск по Id и viewmodel на каждый товар. Нужны карта по Id и viewmodel только для видимых строк.
- **Отменённый диалог.** Если загрузку класса диалога отменили, запросивший не получит ответа.

## Чего пока нет

- Автоматических проверок. Гонки роутера я проверял вручную в запуске `-game -nullrhi` через консольные команды `Relay.UI.*`, а геймпад, клавиатуру и фокус - в Play In Editor. Automation Spec для роутера в планах.
- Blueprint API для открытия экранов: экраны открываются только из C++ и данных.
- Сохранения покупок и анимаций у тостов и диалогов.
- Русского перевода: переключатель языка в настройках есть, перевод ещё не собран.

## Настройки, которые ломаются молча

- Project Settings > Common Input Settings > Input Data указывает на `BP_RelayUIInputData`, где действие Back - `IA_UI_Back`. Без этого Back ничего не делает, а CommonUI пишет в лог «Cannot create action binding».
- У `IMC_UI` в Input Mode Filter Options стоит Do Not Filter.
- У шаблонных `IMC_Default` и `IMC_MouseLook` свой фильтр режима ввода по `InputMode.Game`.
- `IA_UI_Back` и `IA_UI_OpenMenu` лежат в одном контексте: у них общие Escape и Start.
- В `WBP_NavButton` и `WBP_Button` есть виджет `FocusFrame`, по умолчанию Hidden. Без него фокус с клавиатуры не виден.
- Привязку MVVM к виджету, которого нет (например, к вложенному в кнопку `InputActionWidget`), компилятор WBP пропускает. Во время игры она не выполняется, а в логе появляется ошибка `Invalid Destination` категории Model View Viewmodel.
- У корня HUD нельзя запрещать попадания для всех дочерних виджетов: CommonUI тогда отключает привязки HUD, и горячая клавиша меню перестаёт работать. Прятать нужно внутренние панели.

## Особенности редактора

- В Play In Editor CommonUI применяет режим ввода и фокус, только пока окно игры в фокусе. Поэтому роутер, построив UI, в редакторе сам отдаёт фокус окну игры. Если фокус потом ушёл в другое окно, после возврата нужно нажать кнопку геймпада или кликнуть по кнопке меню. В собранной игре такой проверки нет.
- Escape в редакторе по умолчанию останавливает Play In Editor. `Config/DefaultEditorKeyBindings.ini` переназначает остановку на Shift+Escape, как в Lyra, поэтому Escape работает как Back. Это действует только в этом проекте.
- Listen server в одном процессе PIE делит одного пользователя Slate между игроками, поэтому во втором окне меню может не блокировать игровой ввод. Запускать с выключенным «Run Under One Process».

## Контент шаблона

Персонаж, контроллер и режим игры из шаблона Third Person лежат в `Source/Relay/Private/Template` с заголовками Epic до геймплейной части. Шаблон добавлял сенсорное управление прямо на экран в обход роутера, поэтому этот код убран.
